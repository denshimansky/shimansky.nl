# shimansky.nl — контекст для Claude

Личный сайт Павла Шиманского (визитка EN/RU/NL + книжный трекер `/books` + коллекция книг и винила
`/collection` + `/api/goodreads`).
Next.js 16 (App Router, standalone), React 19, Tailwind v4. Структура кода и «что править где» — в `README.md`.

Владелец и заказчик — Павел. Сервер его собственный: можно менять что угодно, соседних сайтов тут нет.
Инфраструктуру вокруг (прокси, Hetzner-хост, роутер) администрирует Денис — см. «Когда звать Дениса».

## Где живёт

```
браузер → shimansky.nl (DNS в Namecheap → 89.19.212.181, «autopilot», TimeWeb Франкфурт)
        → nginx на autopilot: только TLS и проксирование — доступа туда нет и не нужно
        → 65.108.45.139:443 → ВМ Павла: nginx → docker-контейнер 127.0.0.1:3020
```

Прокси нужен из-за России: ТСПУ режет прямые соединения к Hetzner (замирают после ~16 КБ),
а TimeWeb не режется. Из NL/EU ВМ доступна и напрямую по 65.108.45.139.

**ВМ**: Ubuntu 24.04, 2 vCPU / 4 ГБ RAM / 40 ГБ, часовой пояс Europe/Amsterdam.
- SSH: `ssh -p 2290 pavel@65.108.45.139` — только по ключу; `sudo` без пароля; `docker` без sudo
- Код: `/opt/shimansky.nl` (git-клон этого репо, владелец `pavel`)
- Контейнер: `shimanskynl-app-1`, `127.0.0.1:3020 → 3000` (см. `docker-compose.yml`)

## Деплой

**Push в `main` = выкладка.** GitHub webhook → `https://shimansky.nl/deploy-webhook` →
`webhook.service` (от `pavel`, `127.0.0.1:9000`, конфиг `/etc/webhook.conf`) →
`/usr/local/bin/deploy-shimansky-nl` → `git pull --ff-only` + `docker compose up -d --build`.

- Выкатывается только `main`. Эксперименты — в других ветках, они никуда не уходят.
- Лог: `/var/log/shimansky-nl-deploy.log`. После пуша проверяй, что там появилось `Deploy complete`.
- Если сборка упала — старый контейнер продолжает работать, сайт не ложится. Причина — в логе.
- **Не правь файлы в `/opt/shimansky.nl` без коммита.** Незакоммиченные правки ломают `git pull --ff-only`,
  и деплой останавливается (`git pull FAILED` в логе). Правишь на сервере — сразу commit + push оттуда же.
- Ручной деплой на ВМ: `cd /opt/shimansky.nl && git pull && docker compose up -d --build`.
- **`package-lock.json` генерируй в Linux**, если меняешь зависимости: lock, собранный на macOS,
  может не содержать linux-optional пакетов (sharp/`@emnapi/*`) — тогда `npm ci` в Docker падает
  «not in sync». Надёжно: `docker run --rm -v "$PWD":/app -w /app node:24-alpine npm install --package-lock-only`.

Проверка после выкладки:
```bash
curl -s -o /dev/null -w "%{http_code}\n" https://shimansky.nl/          # 200
curl -s "https://shimansky.nl/api/goodreads?isbn=9780735211292"         # "rating":4.31
docker ps --format "{{.Names}} {{.Status}}"; docker logs --tail 50 shimanskynl-app-1
```

## nginx и сертификат (на ВМ)

- Сайт: `/etc/nginx/sites-available/shimansky-nl` (симлинк в `sites-enabled`). Там: `location /`, по два
  `location` для `/books` и `/collection` (камера `camera=(self)` для сканера штрихкодов), `/deploy-webhook`, редиректы `www.*`, `shimanskii.nl`,
  `shimanskaya.nl` → `shimansky.nl`, и `:80 → https`.
- Заголовки безопасности: `/etc/nginx/conf.d/security-headers.conf` (уровень `http`). Любой `add_header`
  внутри `location`/`server` отключает наследование — поэтому в `/books` и `/collection` продублированы
  все 6 заголовков. Новый раздел с камерой — по тому же образцу.
  Прокси на autopilot своих заголовков не добавляет: что отдала ВМ, то и видит браузер.
- `conf.d/realip.conf` берёт реальный IP клиента из `X-Forwarded-For` от 89.19.212.181. Не удаляй —
  иначе в логах и в fail2ban будет только адрес прокси.
- Перед каждой перезагрузкой: `sudo nginx -t && sudo systemctl reload nginx`.
- Сертификат Let's Encrypt на все 6 имён: `certbot` на ВМ, продлевается сам (`certbot.timer`, после
  продления хук перезагружает nginx). Проверка домена идёт по HTTP через прокси на `:80` этой ВМ —
  не ломай server-блок `listen 80` для этих имён. После правок nginx: `sudo certbot renew --dry-run`.
- Не удаляй `location /deploy-webhook` — без него автодеплой перестанет работать.

## Сеть: что можно и что нельзя

Снаружи на ВМ проброшены только **80, 443 и SSH 2290**. Другой порт из интернета недоступен —
новые сервисы ставь за nginx на 443 (по пути или по поддомену). Docker-порты публикуй только
на `127.0.0.1:…` (Docker обходит ufw).

Исходящий трафик ограничен на роутере (это не баг, не пытайся обойти):
- закрыт исходящий порт 25 — почту слать через 587/465 или API (Resend, Mailgun и т.п.);
- закрыты внутренние сети и SSH/RDP к серверам ОБРП (к ним открыты только 80/443);
- лимит: ~50 новых соединений в секунду и 500 одновременных TCP — массовые сканы и нагрузочные
  тесты «наружу» будут резаться;
- заблокирован BitTorrent.

**Никогда не запускать на этой ВМ**: торренты, сканеры портов/уязвимостей, подбор паролей, массовые
рассылки, майнинг, публичные VPN/прокси для других. Жалобы (abuse) приходят на аккаунт Hetzner,
на котором живут и другие серверы; у аккаунта уже два инцидента — третий может закончиться блокировкой IP.

## Безопасность

- Держи Next.js и React на свежих патч-версиях: на соседнем сервере старый Next.js 15.0.3 через RCE
  (CVE-2025-55182) превратили в майнер. Периодически `npm outdated` / `npm audit`, обновления — через push.
- Обновления ОС ставятся сами (`unattended-upgrades`). Раз в месяц: `sudo apt full-upgrade`, и если есть
  `/var/run/reboot-required` — `sudo reboot` (сайт поднимется сам: `restart: unless-stopped`).
- Секреты (токены API и т.п.) — в `.env` на сервере, не в git. Репо публичный.

## Не трогать (иначе потеряется доступ к ВМ)

- Сетевые настройки (IP `172.30.67.10/24`, шлюз `172.30.67.1`) — у Павла нет консоли, при ошибке ВМ
  станет недоступна.
- `sshd` и правило ufw для 22/tcp; вход только по ключам — не включай пароли.
- Пользователя `denis` и его ключ — это аварийный доступ Дениса.

## Бэкапы

Вся ВМ бэкапится раз в неделю (воскресенье 03:00, хранятся 3 последних). Код — в git.
Если появятся данные вне git (база, загрузки), делай для них свой бэкап — недельного снимка может не хватить.

## Когда звать Дениса

- нужен новый открытый порт снаружи, новый домен/поддомен или правка DNS (Namecheap — его аккаунт);
- новый домен должен открываться из России (его надо добавить в прокси на autopilot; без этого
  DNS можно направить прямо на 65.108.45.139 — из-за границы заработает);
- ВМ недоступна по SSH, нужна перезагрузка «снаружи», восстановление из бэкапа или больше ресурсов.
